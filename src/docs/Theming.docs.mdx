# Theming

Lagom's look comes entirely from lagom-tokens' CSS custom properties. To change it, you override tokens in your own CSS. Three attributes choose what an element shows, on `<html>` or on any element inside it:

- `data-lagom-brand="…"`: the brand. With no attribute you get **Base**, Lagom's neutral default.
- `data-lagom-theme="dark"`: dark mode. With no attribute you get light mode.
- `data-lagom-contrast="more"`: increased contrast. The `prefers-contrast: more` media query turns it on too.

Every component follows all three. There are no component props or JavaScript settings for colours, fonts, radii, or spacing.

## Making your own brand

Override the tokens you want to change on a `data-lagom-brand` selector, in a stylesheet loaded after `lagom.css`, and set the attribute on `<html>`:

```css
[data-lagom-brand~="rouge"] {
  --lagom-semantic-color-accent-default: #b4281f;
  --lagom-semantic-color-accent-fg: #b4281f;
  --lagom-semantic-color-accent-bg: #fadcda;
  --lagom-semantic-color-focus-ring: #b4281f;
  --lagom-core-font-families-sans-serif: "Inter", sans-serif;
  --lagom-component-button-border-radius: 999px;
}

[data-lagom-brand~="rouge"][data-lagom-theme~="dark"] {
  --lagom-semantic-color-accent-default: #e79690;
  --lagom-semantic-color-accent-fg: #e79690;
  --lagom-semantic-color-accent-bg: #591c14;
  --lagom-semantic-color-focus-ring: #e79690;
}
```

```html
<html data-lagom-brand="rouge"></html>
```

Anything you don't override keeps Base's value. Three rules keep a brand accessible:

- **Set every colour role you change in both modes.** A light-mode accent left on in dark mode usually fails contrast.
- **Set increased-contrast values** for any role that falls short of AAA (7:1 for text, 4.5:1 for borders, button fills, and the focus ring). Set them once under `[data-lagom-contrast~="more"]` and again inside `@media (prefers-contrast: more)`.
- **Check it:** `npx check-brand your-brand.css` (it comes with lagom-tokens) checks every role in light, dark, and both increased-contrast variants, and lists anything that fails.

lagom-tokens' `examples/white-label.css` is a complete brand, including the selectors that let a section switch mode on its own.

**Fern** and **Waypoint**, the brands in Storybook's toolbar, are Frank Congson's own brands for his sites. They're in a separate package, `@fcongson/lagom-brands`, which is public but not licensed for reuse. Base is MIT: start from it.

## What to override

- **Colour:** the `--lagom-semantic-color-*` roles, such as `fg-default`, `bg-secondary`, `accent-default`, `button-primary-bg`, and `focus-ring`. Components read colour only through these roles (directly, or through a component token that points at one), so one override changes every component that uses the role. See [Using tokens](?path=/docs/design-tokens-using-tokens--docs) for every role.
- **Fonts, sizes, radii, and spacing:** the `--lagom-core-*` tokens, such as `--lagom-core-font-families-sans-serif`, `--lagom-core-font-sizes-header1`, or `--lagom-core-border-radius-sm`.
- **One component:** the `--lagom-component-*` tokens:
  - `--lagom-component-button-border-radius`, `-border-width`, and `-color-primary-background`, `-text`, `-border` (and the `secondary` equivalents): `Button` and `LinkButton`
  - `--lagom-component-page-header-typography`, `-color-text`, `-margin-bottom`, `-margin-bottom-sm`: `PageHeader`
  - `--lagom-component-section-header-typography`, `-color-text`, `-margin-bottom`: `SectionHeader`
  - `--lagom-component-hero-margin-bottom`, `-margin-bottom-sm`, `-image-fit`: `Hero`
  - `--lagom-component-featured-section-color-background`, `-color-text`, `-image-fit`: `FeaturedSection`
  - `--lagom-component-image-overlay-color-background`, `-opacity`: the overlay over `Hero` and `FeaturedSection` images

`PageHeader` and `SectionHeader` step down the header scale on smaller screens: `PageHeader` uses `--lagom-core-font-sizes-header1`, then `header2` at 992px and below, then `header3` at 568px and below. `SectionHeader` starts at `header2`.

## Dark mode

Set `data-lagom-theme="dark"` on `<html>` for a dark page, or on any element for a dark section:

```html
<html data-lagom-theme="dark">
  …
</html>

<section data-lagom-theme="dark">This section is dark.</section>
```

Dark mode changes the colour roles, makes image overlays stronger, and dims images slightly (`--lagom-semantic-image-filter`). Use `--lagom-semantic-color-*` roles in your own CSS so it switches too.

## Increased contrast

`data-lagom-contrast="more"`, or the user's `prefers-contrast: more` setting, switches every role to values that pass WCAG AAA: 7:1 for text and 4.5:1 for borders, button fills, and the focus ring. Borders get thicker (2px) and so does the focus ring (3px). Use it for a site-wide accessibility toggle, or leave it to the user's system setting.

## Focus

Everything focusable gets the brand's focus ring for keyboard focus (`:focus-visible`): an outline in `--lagom-semantic-color-focus-ring`, `--lagom-semantic-focus-ring-width` wide, 2px from the element. Over images (inside `Hero`, or an image-background `FeaturedSection`), the ring gets two more bands, `bg-default` inside and `fg-default` outside, so it shows on any image. In forced colours (such as Windows High Contrast) the ring uses the system highlight colour.

## Changing part of a page

Put a `data-lagom-brand`, `data-lagom-theme`, or `data-lagom-contrast` attribute on any element to change everything inside it, including tokens built from other tokens.

To change one thing in one area without a brand, override **the token the component reads**, the `--lagom-component-*` token, on a wrapping element. For example, purple primary buttons in one section:

```css
.promo {
  --lagom-component-button-color-primary-background: #6b3fa0;
  --lagom-component-button-color-primary-border: #6b3fa0;
  --lagom-component-button-color-primary-text: #ffffff;
}
```

Overriding a semantic role there instead (`.promo { --lagom-semantic-color-button-primary-bg: … }`) does **not** change the buttons. Custom properties resolve where they're declared: the component token was already resolved from the role on `<html>`, so the buttons keep the page's value. The same goes for any token built from another (`button-primary-bg` from `accent-default`, for example). Semantic role overrides only reach components on `:root` or a brand selector.

If the area needs a different look in dark mode or with increased contrast, set the component tokens again for those (as in the brand example above), and check the contrast yourself.

## Layout properties

A few layout values aren't tokens. Set them in CSS:

- `--hero-height`: `Hero` height, default `100vh`.
- `--featured-section-height`: image-background `FeaturedSection` height, default `auto`.
- `--framed-margin`: inset for `framed` FeaturedSections, default `1rem`.

## `createTheme()`

`createTheme()` builds the `theme` object that `ThemeProvider` passes to `useTheme()`: layout widths, breakpoints, and ready-made media queries, for your JavaScript. It doesn't change how components look.

```jsx
import { createTheme, ThemeProvider } from "@fcongson/lagom-ui";

const { theme } = createTheme({ MAX_WIDTH_CONTAINER: 960 });

export const App = ({ children }) => (
  <ThemeProvider theme={theme}>{children}</ThemeProvider>
);
```

It accepts `MAX_WIDTH_SECTION`, `MAX_WIDTH_CONTAINER`, and `MAX_WIDTH_CONTENT`. **Changing them doesn't change Lagom's CSS:** Section stays 1800px wide and Container 1120px.

## Upgrading from lagom-ui 1.x

lagom-ui 2.0 removes the `--themed-*` hooks and `createTheme()`'s `core`, `button`, and `GlobalStyle`. Override the token instead:

- `--themed-core-font-families-sans-serif`, `-serif`, `-monospace` → `--lagom-core-font-families-sans-serif`, `-serif`, `-monospace` (body text and headings read `--lagom-core-font-families-body` and `-heading`, which point at `sans-serif` in Base)
- `--themed-core-font-sizes-body` → `--lagom-core-font-sizes-body`
- `--themed-core-font-weights-semi-bold` → `--lagom-core-font-weights-semi-bold`
- `--themed-header-scale-1` … `-6` → `--lagom-core-font-sizes-header1` … `header6`
- `--themed-component-*` → the `--lagom-component-*` token with the same name
- `createTheme({ core, button })` → set the same tokens in CSS

lagom-tokens 2.0 also renamed some roles (`fg-muted` is now `fg-secondary`, for example). Its `MIGRATION.md` lists every change, and `scripts/migrate.js` rewrites them for you.
